# School function choice and access requests

The web app now links to `/school-role.html` from home, profile and administration. After first onboarding, a signed-in account without a stored choice is directed to this screen. The choice is stored per account, not per device. School uses only its dedicated backend and auth storage key.

Four choices: open-class student, training student, teacher, team. A choice never grants a profile role or a training-group membership. All four flows submit campus-specific requests. Open students specify their classes/disciplines. Formation students select an existing P1/P2/P3 group and season from a metadata-only RPC; server validation checks that the group belongs to the campus. Student validation uses jds_review_student_request, never the generic teacher/team review RPC.

Teacher and team applications are campus-specific. Email confirmation is required. Pending applications are idempotent; rejected applications can be resubmitted. Approved applications cannot be edited by applicants. Applicants can read only their own requests. Direct INSERT/UPDATE/DELETE on requests are not granted to clients.

Teacher review: central administrators, enabled Nicolas/Bruce responsibilities across campuses, enabled Rabah/Loïc responsibilities for their own campus. Jacky cannot validate teachers. Student/open applications can be reviewed by central administrators or enabled school responsibilities for the relevant campus, including Jacky for INDUSTRY. Formation approval requires an explicit roster identity selection in that group. The transaction verifies the directory record, records the decision and reviewer, and links the authenticated account to that exact training membership. A different account cannot be overwritten; a second class in the same season is blocked. Open approval creates no training membership. Team applications require central administrators or enabled Nicolas/Bruce responsibilities. No self approval. Decisions are locked, timestamped and attributed to the reviewer. Optional decision notes are visible to applicants.

A teacher approval records a campus-scoped entitlement in the approved request. Class assignments, bulletin structure and publication remain separate pending the school's model. Team approval does not create an administrator role: responsibilities still require explicit linking to a verified School account. None of the five team accounts existed at the last check; prepared responsibilities remain disabled. Nicolas's prepared responsibility covers both schools.

Validation: `supabase/tests/school_access_requests.sql` runs synthetic identities and temporary responsibility bindings inside BEGIN/ROLLBACK. It covers student self approval, campus isolation, director vs team review, Jacky exclusion, Nicolas global scope, approval receipt, duplicate submission, rejected resubmission, and missing anonymous/direct write grants. All temporary data is rolled back.

Web build: use pinned @supabase/supabase-js 2.110.1 and esbuild 0.25.12 to bundle web-access/access.js into public/assets/school-access.js; config.js contains only the dedicated School public publishable key. Copy school-role.html and school-access.css into public. The existing static export includes the gate script and gate-only stylesheet; global portal CSS must not be included in the Expo shell. No native binary was rebuilt.

Student extension validation: supabase/tests/school_student_enrollment.sql covers wrong campus/class, pending access isolation, self review, Jacky scope, generic RPC bypass, wrong roster identity, transactional membership link and audit receipt, open-vs-formation separation, unchanged global roles and anonymous rejection. Synthetic data is rolled back. web-access/test-ui.cjs covers teacher/open/formation form submission and filtered class options.

Explicit team activation: central administrators can view account readiness and activate the five reserved responsibilities from the function/access page. The activation RPC requires the exact reserved email on an existing verified, unbanned School account. Nicolas and Bruce receive the global admin role; Rabah, Loïc and Jacky receive only their enabled campus responsibility. Existing links cannot be overwritten. Activation records activated_at and activated_by and is idempotent. No signup, email confirmation or role request activates staff automatically. school_team_activation.sql tests unconfirmed rejection, applicant rejection, metadata isolation, Nicolas global rights, director campus scope and audit receipt inside rollback.
